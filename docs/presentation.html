ad — animate a diff

Watch your code changes come alive, character by character, as if a human were typing them.

C / C++ / Perl / Bash Plugin Layers Linux / macOS v2.0

What is ad?

ad is a toolkit that animates code diffs. It opens the old version of a file and progressively transforms it into the new version, character by character, as if a human were typing the changes. The cursor glides between change locations with smooth ease-in-out acceleration, and only the actually-changed characters are deleted and re-typed — surrounding text is never touched.

ad_vim is the vim application — one consumer of the toolkit — that renders the animation inside vim. You can pause, skip, rewind, and change speed at any moment.

Get started in 30 seconds

⚡ Quick start

Option 1: Build from source

# Clone and build
git clone https://github.com/nkh/gitanim.git
cd gitanim
make

# Animate a diff in vim
./apps/vim/ad_vim old.py new.py

# Or run the full pipeline (terminal output)
./pipeline/ad_pipeline old.py new.py

Option 2: Homebrew (macOS)

# Install via Homebrew formula
brew install ./packaging/ad_vim.rb
ad_vim old.py new.py

Option 3: Vim plugin

# In vimrc with vim-plug:
Plug 'nkh/gitanim', {'rtp': 'apps/vim'}

# Then in vim:
:Diffvim old.py new.py

Controls during animation

While the animation is running in vim, these keys are active:

KeyAction
SpacePause / resume (or advance one op in step mode)
nSkip current hunk — apply instantly, move to next
bBack to previous hunk — revert and restart it
qStop animation (leave buffer in current state)
+Speed up (×1.5)
-Slow down (×0.67)
=Reset speed to 1.0×
?Show in-vim help

These controls work in normal mode. The animation runs in vim's buffer using timer-based rendering — no tmux, no external terminal tricks. The buffer is real, the cursor is real, the syntax highlighting is real.

The pipeline is modular: each stage reads V2 TSV from stdin and writes V2 TSV to stdout. Stages are independent executables — you can run any layer standalone for debugging.

Plugin layer system

Postprocess layers are standalone executables that transform the op stream. The orchestrator (ad_postprocess) chains them in the order you specify on the command line.

# List available layers
./pipeline/ad_postprocess --list-layers

# Run a specific chain
./pipeline/ad_postprocess --ad-layer=ad_layer_reorder --ad-layer=ad_layer_indent_last --ad-layer=ad_layer_pace

# Add a custom layer from any language
./pipeline/ad_pipeline --ad-layer=my_custom_layer old.py new.py

# Add a custom layer from a specific path
./pipeline/ad_pipeline --ad-layer=/path/to/my_layer.sh old.py new.py

# Add a search path for layers
./pipeline/ad_pipeline --ad-layer-path=/my/layers --ad-layer=my_layer old.py new.py

Layers run in argv order — not sorted, not deduplicated. The same layer can be passed twice (it runs twice). Extensions are honored: .pl → perl, .py → python3, .rb → ruby, .sh → bash, .js → node. No extension = must be executable.

Popular option combinations

# Basic animation
ad_vim old.py new.py

# Fast review — skip pacing, just show the diff
ad_vim --speed 5 --no-display --snapshot out.txt old.py new.py

# Slow, dramatic — for presentations
ad_vim --speed 0.5 --pacing gaussian --highlight inline old.py new.py

# Code review — highlight hunks, dim unchanged
ad_vim --highlight hunk --dim-unchanged --context 3 old.py new.py

# Overwrite mode — replace in place instead of delete+insert
ad_vim --overwrite --indent-last old.py new.py

# Custom layer chain
ad_vim --ad-layer=ad_layer_reorder --ad-layer=my_word_split --ad-layer=ad_layer_pace old.py new.py

# Snapshot every op to HTML (for documentation)
bash scripts/ad_snapshot.sh old.py new.py
# Open: file:///tmp/ad_snapshots/snapshots.html

Configuration — no env vars

Configuration comes from a single file, with CLI flags overriding per-invocation. There are no environment variables.

Config file location

$XDG_CONFIG_HOME/ad/config (defaults to ~/.config/ad/config)

Precedence

1. /etc/ad/config        (system-wide defaults, lowest priority)
2. ~/.config/ad/config   (user config)
3. CLI flags             (per-invocation, highest priority)

Example config file

# ~/.config/ad/config
DELETE_PACING=word
INSERT_PACING=char
PACING=uniform
INDENT_LAST=1
OVERWRITE_MODE=1
CURSOR_GLIDE_MS=100
HIGHLIGHT_MODE=inline
HIGHLIGHT_DURATION_MS=200

Every CLI flag has a config variable equivalent. Run ad_vim --help for the full list.

Diff engine

The diff engine computes a character-level diff using the Patience algorithm (anchored on unique common lines, with LCS fallback for ranges with no anchors).

C++ (preferred)
diff_engine/cpp/compute.cpp → bin/ad_compute
~1ms on a 1000-line file. 318× faster than the old vimscript Patience.
Perl (fallback)
diff_engine/perl/compute.pl
Pure-Perl fallback used when the C++ binary is missing. Produces identical output.
# Compute the diff
./bin/ad_compute old.py new.py raw_ops.txt

# With left-to-right sorting
./bin/ad_compute --left-to-right old.py new.py raw_ops.txt

# Benchmark on a 1000-line Python file:
  Perl compute:       ~3500 ms
  C++ ad_compute:     11 ms   (318× faster)

Cursor glide geometry

The cursor doesn't jump between hunks. It glides with ease-in-out cubic acceleration, so the viewer's eye can follow even long jumps.

  Hunk 1 (line 3)          Hunk 2 (line 47)         Hunk 3 (line 92)
     │                        │                        │
     ▼                        ▼                        ▼
  ────████████████████████████████████████████████████████████────
       ↑  ease-in    ↑  constant   ↑  ease-out
       acceleration   velocity      deceleration

  Duration = clamp(move_min_ms + distance × move_ms_per_unit, move_min_ms, move_max_ms)

The glide is interpolated frame-by-frame at --tick-ms intervals (default 16ms = ~60fps). Intermediate cursor positions can be shown or hidden with --cursor-glide-show-intermediate.
